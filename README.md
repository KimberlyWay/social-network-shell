# Социальная сеть — учебная оболочка для Android

Простое приложение на Kotlin с обычной XML-разметкой. Четыре раздела: лента новостей с картинками, люди и друзья, сообщения, профиль. По уровню устройства это небольшой студенческий проект: две Activity, встроенные примеры данных и локальное сохранение настроек.

[Скачать APK и исходники из релиза](https://github.com/KimberlyWay/social-network-shell/releases/latest) · [Сборки Actions](https://github.com/KimberlyWay/social-network-shell/actions) · [Исходники main в ZIP](https://github.com/KimberlyWay/social-network-shell/archive/refs/heads/main.zip)

Это именно **оболочка**: сервер и аккаунты не требуются, сообщения остаются на телефоне. Интернета и разрешений приложение не запрашивает. Для демонстрации входящих сообщений в некоторых диалогах заранее записана история. Автоматических ответов и связи между разными телефонами нет.

## 1. Что работает

| Раздел | Возможности |
|---|---|
| Лента | Просмотр трёх публикаций с автором, условным временем, текстом и иллюстрацией; прокрутка |
| Друзья | Поиск шести демонстрационных пользователей по имени или городу; добавление и удаление друзей; переход в чат |
| Сообщения | Список диалогов, готовые входящие реплики, ввод своих сообщений, отображение пузырьков и времени; отдельное «Избранное» |
| Профиль | Изменение имени, города и текста «О себе»; выбор своего фото из галереи; количество друзей |

В начале добавлены два друга: Анна Смирнова и Максим Орлов. У Анны и Максима есть примеры входящих сообщений. У остальных пользователей и в «Избранном» история пуста до первого сообщения.

Во вкладке «Друзья» показываются все демонстрационные пользователи. У добавленных есть подпись «В друзьях» и кнопка «Убрать», у остальных — «Добавить». Счётчик найденных людей относится к текущему поиску, счётчик друзей — ко всему сохранённому списку.

Сообщения и список людей не зависят от сервера. Добавление в друзья не создаёт запрос реальному человеку. Удаление из друзей не стирает локальную переписку. Написать можно любому из демонстрационных пользователей.

## 2. Как пользоваться приложением

1. Открыть «Социальная сеть». Сразу появится лента, без входа.
2. Пролистать новости. Картинки встроены в приложение и доступны даже в авиарежиме.
3. Нажать «Друзья». Ввести, например, `Самара` или `Мария`. Поиск не учитывает регистр и пробелы по краям.
4. Нажать «Добавить» возле найденного человека. Надпись изменится на «Убрать», а число друзей увеличится.
5. Нажать «Написать» либо перейти в «Сообщения» и открыть нужный диалог.
6. Ввести текст и нажать «Отправить». Сообщение появится справа. Пустая строка или одни пробелы не отправляются.
7. Нажать «Назад», чтобы вернуться. В списке диалогов появится последняя реплика.
8. В «Профиле» изменить поля и нажать «Сохранить».

В обычных чатах поясняющая подпись скрыта. В «Избранном» оставлено пояснение о локальных заметках. У Анны и Максима есть встроенные фото-аватары, у остальных людей — инициалы.

В «Избранное» можно писать заметки самому себе. Здесь нет статусов доставки и прочтения: текст только сохраняется на устройстве.

Имя не должно быть пустым. Максимум для имени и города — 60 символов, для «О себе» — 300, для одного сообщения — 2000. Обычные переносы строки в сообщениях поддерживаются. В профиле кнопка «Выбрать фото» открывает системный выбор изображения. Фото сохраняется сразу, отдельно от кнопки «Сохранить» для текстовых полей. Изображение обрезается по центру до квадрата, уменьшается до 256 × 256 и отображается в круге. Если своего фото нет, используются инициалы. Можно выбирать изображения размером до 20 МБ; отмена выбора или ошибка оставляет предыдущее фото.

## 3. Где хранятся данные

Текст профиля, список друзей и отправленные сообщения сохраняются через стандартный Android `SharedPreferences`. Базы данных SQLite/Room нет. Для каждой переписки список сообщений записывается как текст JSON в отдельное значение настроек.

- После закрытия и повторного открытия приложения сохранённые данные остаются.
- При смене вкладок введённые поля профиля остаются на экране, но для постоянного сохранения нужна кнопка «Сохранить».
- При повороте Android восстанавливает текст полей; выбранная вкладка дополнительно сохраняется в `Bundle`.
- История у каждого диалога отдельная.
- После удаления приложения или очистки его данных локальные записи исчезают.
- На другом телефоне будет новая независимая копия, без синхронизации.

Фото профиля хранится отдельным файлом `profile_avatar.jpg` во внутреннем каталоге приложения. Из галереи делается собственная уменьшенная копия: после выбора не нужен постоянный доступ к исходному файлу. Разрешения `READ_MEDIA_IMAGES` и доступа ко всему хранилищу не запрашиваются. Приложение получает доступ только к выбранному изображению через `ACTION_OPEN_DOCUMENT`. Декодирование и сохранение выполняются в фоновом потоке; для JPEG учитывается EXIF-поворот. Для форматов, которые не поддерживает системный декодер устройства, показывается сообщение об ошибке.

Входящие реплики — демонстрационные данные в `LocalStorage.kt`. Пока в диалог не отправлено своё первое сообщение, пример истории создаётся в памяти с временем относительно текущего момента. После первой отправки вся история этого диалога, включая примеры, записывается с конкретными отметками времени.

SharedPreferences выбраны для небольшого учебного примера. При каждой отправке записывается вся история одного диалога. Такой подход не рассчитан на тысячи сообщений; для настоящего мессенджера потребовалось бы другое хранилище и сервер.

| Компонент | Значение |
|---|---|
| Kotlin | 2.0.21 |
| Android Gradle Plugin | 8.7.3 |
| Gradle | 8.9 |
| Java для сборки | JDK 17 |
| compileSdk | 35 |
| targetSdk | 34 |
| minSdk | 21 — Android 5.0 |
| Идентификатор приложения | `com.example.socialnetwork` |
| Текущая версия | `versionName = "1.1"`, `versionCode = 2` |

Версии заданы в Gradle-файлах. Это конфигурация учебной APK для установки напрямую; актуальные требования Google Play к публикации отдельно не проверяются.

На компьютере нужны Android Studio, Android SDK и интернет для первого скачивания Gradle и плагинов. На телефоне интернет не нужен. Проект использует платформенные Android Activity, LinearLayout, ScrollView, TextView, EditText и Button. Compose, AppCompat, серверные SDK и сторонние библиотеки интерфейса не подключены.

## 5. Как открыть в Android Studio с нуля

### Скачать

1. Открыть репозиторий на GitHub.
2. Выбрать `Code → Download ZIP` или скачать ZIP исходников из релиза.
3. Распаковать архив, например в `C:\Projects\SocialNetworkShell`.
4. Найти внутри файл `settings.gradle.kts`.

Не открывать проект внутри ZIP. В архиве GitHub уже нет каталога `.git`, Git для работы с ZIP не нужен.

Другой вариант — `Clone Repository` / `Get from VCS` в Android Studio с адресом:

```text
https://github.com/KimberlyWay/social-network-shell.git
```

### Открыть и дождаться синхронизации

1. В Android Studio нажать `Open` либо `File → Open`.
2. Выбрать **корневую папку с `settings.gradle.kts`**, а не вложенную `app`.
3. Подтвердить доверие к проверенным исходникам, если Studio спросит.
4. Дождаться Gradle Sync и загрузки зависимостей.
5. В `Tools → SDK Manager` установить Android SDK Platform 35 и Build Tools 34.0.0, если они ещё не установлены.
6. В `Settings → Build, Execution, Deployment → Build Tools → Gradle` выбрать Gradle JDK 17. При отсутствии версии можно воспользоваться `Download JDK`.

Названия меню отличаются между версиями Android Studio. Не обязательно обновлять AGP и Gradle при первом открытии: сначала стоит собрать проект с указанными версиями.

`local.properties` с путём к SDK обычно создаётся Studio автоматически. Его не нужно переносить с чужого компьютера или загружать в Git.

### Если Gradle не скачивается

Gradle Wrapper скачивает Gradle 8.9 по адресу из `gradle/wrapper/gradle-wrapper.properties`. Для первого запуска нужен доступ к дистрибутиву Gradle и репозиториям плагинов Google/Maven.

1. Посмотреть точный текст в окне `Sync` / `Build Output`.
2. Проверить доступ в интернет и выключенный Gradle Offline Mode.
3. Если используется прокси, проверить настройки `HTTP Proxy` в Studio и настройки Gradle.
4. Повторить `Sync Project with Gradle Files`.

Ошибка скачивания не всегда означает ошибку проекта. Для диагностики нужны конкретные адрес и сообщение: например, timeout, неизвестный хост, SSL или несовместимая Java. Не стоит менять версии наугад.

## 6. Запуск на телефоне и эмуляторе

### Телефон

1. Включить параметры разработчика Android — обычно несколькими нажатиями на номер сборки в сведениях о телефоне.
2. Включить «Отладку по USB».
3. Подключить телефон кабелем с передачей данных.
4. Подтвердить разрешение отладки на телефоне для своего компьютера.
5. Выбрать устройство и конфигурацию `app` в Android Studio.
6. Нажать зелёную кнопку `Run`.

Если устройство не появилось, проверить кабель, USB-режим, разрешение отладки и драйвер на Windows.

### Эмулятор

Открыть `Tools → Device Manager`, создать виртуальный телефон, скачать system image Android с API 21 или новее и запустить его. Затем выбрать эмулятор как устройство и нажать `Run`.

## 7. Как собрать и установить APK

Через Android Studio найти в `Build` действие сборки APK: обычно `Build Bundle(s) / APK(s) → Build APK(s)` либо `Generate App Bundles or APKs → Generate APKs`. Для учебного запуска выбрать `debug`.

Независимый от названий меню вариант — терминал из корня проекта.

Windows PowerShell:

```powershell
.\gradlew.bat lintDebug assembleDebug
```

Linux / macOS:

```bash
chmod +x gradlew
./gradlew lintDebug assembleDebug
```

Готовый установочный файл находится здесь:

```text
app/build/outputs/apk/debug/app-debug.apk
```

`lintDebug` выполняет статическую проверку Android Lint, `assembleDebug` собирает APK. Это не автоматический запуск интерфейса на телефоне.

Передать APK на телефон, открыть его файловым менеджером и при необходимости разрешить установку из этого источника. Версия Android телефона должна быть не ниже 5.0.

### Подпись и повторные установки

Используется debug-подпись, которую создаёт Android SDK. Секретный release-ключ в репозиторий не добавлен.

У локальной сборки и у сборки GitHub Actions подписи могут отличаться. Новый runner GitHub Actions также может создать другой debug-ключ. Если Android отказывается обновлять установленное приложение из-за подписи, можно удалить старую копию и поставить новую. **При удалении пропадут её локальные сообщения, профиль и список друзей.**

Для регулярных обновлений с сохранением пользовательских данных потребуется постоянный ключ подписи. В данном учебном проекте он не настраивался.

## 8. GitHub Actions и релизы

Настройка находится в `.github/workflows/android.yml`.

Workflow запускается:

- при отправке изменений в `main`;
- при открытии или обновлении pull request;
- вручную: `Actions → Build APK → Run workflow`;
- при отправке тега, начинающегося с `v`, например `v1.0.0`.

Задача `build` устанавливает Java 17 и SDK, затем запускает `lintDebug assembleDebug`. Полученный APK сохраняется в artifact `social-network-shell-apk` на 30 дней.

Для скачивания artifact открыть успешный запуск во вкладке `Actions`, внизу выбрать `social-network-shell-apk`, скачать ZIP и распаковать `app-debug.apk`. Через интерфейс GitHub для artifacts обычно требуется вход в аккаунт.

### Публикация в Releases

Для тега `v*` после успешной сборки дополнительно запускается задача `release`. Она:

1. Скачивает APK, полученный задачей `build` в этом же запуске.
2. Переименовывает его в `social-network-shell-v1.0.0.apk` для тега `v1.0.0`.
3. Делает ZIP исходников **из того же коммита**, включая README и Gradle Wrapper.
4. Создаёт релиз с этими двумя вложениями и описанием из `RELEASE_NOTES.md`.

Пример команд для следующего релиза после изменения версии приложения и отправки коммита:

```bash
git tag v1.0.1
git push origin v1.0.1
```

Это пример, не команда для повторной публикации уже существующего тега. Номер версии Android в `app/build.gradle.kts` и имя Git-тега меняются отдельно.

Для автоматического релиза используется временный `GITHUB_TOKEN`, который GitHub выдаёт workflow. Задача сборки имеет `contents: read`, а задача релиза — `contents: write`. Личный токен в проекте и Secrets не требуется.

Повторный запуск задачи публикации для уже существующего релиза может завершиться ошибкой: для нового выпуска нужно использовать новый тег. Наличие исходников не означает, что сборка уже прошла; результат проверяется по зелёному запуску Actions и наличию APK.

## 10. Как связаны экраны и код

### Запуск приложения

В `AndroidManifest.xml` для `MainActivity` объявлены `MAIN` и `LAUNCHER`. Это стартовый экран. Android вызывает его `onCreate()`, а `setContentView(R.layout.activity_main)` подключает XML.

`findViewById(...)` находит элементы по ID из XML. Класс `R` создаёт система сборки по ресурсам: вручную его писать не нужно.

### Навигация

`ViewFlipper` содержит четыре включённые разметки в порядке: лента, друзья, сообщения, профиль. `displayedChild` — номер видимого раздела от 0 до 3. Нижние кнопки вызывают `showPage(index)` и меняют этот номер. Выбранная кнопка подсвечивается.

Чат — вторая Activity. Открывается через `Intent` с дополнительным параметром `chat_id`. Это ID пользователя или строка `saved` для «Избранного». `ChatActivity` проверяет ID, чтобы не открыть несуществующий диалог. Кнопка «Назад» вызывает `finish()`.

`onResume()` основного экрана обновляет список диалогов после возвращения из чата, поэтому последняя реплика видна сразу.

### Пользователи и новости

В `DemoData.kt` описаны простые `data class`:

```kotlin
data class Person(val id: String, val name: String, val city: String, val avatar: Int = 0)
data class Post(val author: String, val time: String, val text: String, val picture: Int)
data class Profile(val name: String, val city: String, val about: String)
data class Message(val text: String, val outgoing: Boolean, val timestamp: Long)
```

`data class` хранит данные. `String` — текст, `Boolean` — true/false, `Long` — целое число для времени в миллисекундах. `picture` содержит ID ресурса картинки, например `R.drawable.post_river`.

`object DemoData` — один объект с общими демонстрационными списками. `listOf(...)` создаёт список. Значения `val` не допускают повторного присваивания ссылки.

В ленте метод `showFeed()` перебирает `DemoData.posts`, создаёт карточку, добавляет автора, время, `ImageView` и текст. Иллюстрации описаны в векторных XML через `pathData`. Это встроенные рисунки, а не загружаемые из интернета фотографии. Время публикаций «Сегодня»/«Вчера» — статическая учебная подпись.

### Поиск и друзья

`TextWatcher` вызывает `showPeople()` после изменения строки поиска. Запрос обрезается через `trim()`, а `filter` оставляет пользователей с совпадением в имени или городе:

```kotlin
it.name.contains(query, true) || it.city.contains(query, true)
```

`true` здесь означает поиск без учёта регистра, `||` — логическое «или». Пустой запрос показывает всех.

`toggleFriend(id)` получает сохранённое множество ID, делает его копию, добавляет или удаляет ID и записывает результат. Копия нужна потому, что множество, возвращённое SharedPreferences, нельзя изменять напрямую. Имена пользователей не используются как ключи — ключами служат стабильные ID вроде `anna`.

### Сообщения

`getMessages(chatId)` возвращает историю выбранной переписки. Если сохранённой истории ещё нет, используются примеры из `demoMessages(chatId)`.

Кнопка «Отправить» берёт текст, убирает пробелы по краям и, если текст не пуст, вызывает `sendMessage()`. Метод добавляет объект `Message` со значением `outgoing = true` и временем `System.currentTimeMillis()`. Затем список превращается в `JSONArray` и сохраняется строкой.

`outgoing = true` размещает пузырёк справа с голубоватым фоном; `false` — слева со светлым фоном. Время показывается через `SimpleDateFormat("HH:mm")`. Это время на устройстве, а не метка сервера. После отправки поле очищается, история перерисовывается, прокрутка уходит вниз.

### Профиль

`fillProfile()` получает сохранённые значения и заполняет поля. `saveProfile()` проверяет имя и вызывает `storage.saveProfile(...)`. В SharedPreferences записываются строки `name`, `city`, `about`.

`apply()` сразу обновляет значения в памяти и асинхронно записывает их на диск. Хранилище открыто с `MODE_PRIVATE`, то есть обычным приложениям доступ к нему не выдаётся. Это не сквозное шифрование и не механизм авторизации.

### Единицы размеров

В XML `dp` задаёт размеры и отступы, `sp` — размер текста с учётом настроек пользователя. В Kotlin вспомогательный метод `dp()` переводит dp в пиксели экрана. `layout_weight` позволяет кнопкам и контейнерам делить свободное место. `ScrollView` добавляет прокрутку, когда содержимое не помещается.

## 11. Как изменить данные и оформление

### Добавить человека

Поле `avatar` — ID картинки (`R.drawable.avatar_anna`); значение `0` оставляет инициалы. Фото для Анны и Максима созданы встроенным генератором по запросу: «квадратный реалистичный аватар вымышленной взрослой женщины / мужчины, обычный портрет при дневном свете, без текста».

В список `DemoData.people` добавить запись с уникальным ID:

```kotlin
Person("pavel", "Павел Кузнецов", "Самара")
```

Это пример для добавления; в исходном наборе такого человека нет. ID должен быть новым и не равняться `saved`. После пересборки пользователь появится в поиске и в списке диалогов.

### Добавить публикацию

В `DemoData.posts` добавить:

```kotlin
Post("Павел Кузнецов", "Сегодня, 12:00", "Текст новой записи", R.drawable.post_river)
```

Записи в списках разделяются запятыми. Если нужна новая картинка, добавить ресурс в `app/src/main/res/drawable` и сослаться на него через `R.drawable.имя`. Для файла `my_picture.png` ссылка будет `R.drawable.my_picture`. Имена ресурсов: маленькие латинские буквы, цифры и подчёркивания, без пробелов и дефисов.

### Изменить входящие сообщения

В `LocalStorage.demoMessages()` изменить сообщения для нужного ID. Для входящего поставить `outgoing = false`. Если на устройстве уже сохранена история диалога, правка начального примера её не заменит. Для возврата к исходным данным можно очистить данные приложения в настройках Android; это удалит и другие локальные изменения.

### Изменить начальный профиль и друзей

Начальные значения профиля находятся в `LocalStorage.getProfile()`, начальные друзья — в `getFriends()`. Они используются только при отсутствии сохранённых значений. Отредактированный пользователем профиль не перезаписывается при обновлении экрана.

### Изменить название и цвета

`app_name` в `strings.xml` — название в списке приложений. Подписи экранов находятся там же. Общие цвета — в `styles.xml`, фоны карточек и сообщений — в `drawable`. Некоторые цвета динамически создаваемых надписей и навигации указаны непосредственно в Kotlin.

### Версия приложения

В `app/build.gradle.kts` для обновления увеличить `versionCode` и поменять `versionName`, например:

```kotlin
versionCode = 3
versionName = "1.2"
```

Сохранить изменения, пересобрать APK и установить. Правка исходников не меняет уже установленное приложение сама по себе.

## 12. Какие файлы можно удалить после открытия в Studio

**Git хранит историю, Gradle собирает приложение.** Файлы Gradle после открытия в Android Studio остаются нужными.

Сначала сохранить копию проекта. Для очистки служебных каталогов закрыть Studio и остановить сборки. При необходимости включить показ скрытых файлов в файловом менеджере.

### Можно убрать из отдельной локальной копии, если GitHub больше не нужен

| Что | Что изменится |
|---|---|
| `.git/`, если проект клонирован | Удалится локальная история, ветки и привязка к репозиторию. Код останется. Репозиторий на GitHub не удалится. |
| `.github/` | Локальной сборке не нужен. При удалении из самого репозитория перестанут работать Actions и автоматические релизы. |
| `.gitignore` | На APK не влияет; нужен для удобной работы с Git. |
| `README.md` | Исчезнет инструкция. |
| `RELEASE_NOTES.md` | Локальной сборке не нужен; автоматическая публикация релиза использует его, поэтому для Actions оставить. |

В ZIP из GitHub нет `.git` изначально. `.github` и `.git` — разные каталоги. Если продолжаете собирать APK через GitHub, **не удалять `.github` и `RELEASE_NOTES.md` из репозитория**.

После удаления `.git` Studio может оставить предупреждение о привязке VCS. Убрать запись этой папки в `Settings → Version Control → Directory Mappings`, если предупреждение появляется.

### Можно очистить, они создадутся заново

| Что | Последствие |
|---|---|
| `.gradle/` и `.kotlin/` внутри проекта | Удалятся локальные данные инструментов; следующая сборка может идти дольше. |
| `build/`, `app/build/` | Удалятся результаты сборки, APK и отчёты. Нужный APK сначала скопировать отдельно. |
| `.idea/`, `*.iml` | Studio пересоздаст служебные настройки; часть местных предпочтений потеряется. |
| `local.properties` | Studio должна заново определить путь к SDK; для терминальной сборки он может потребоваться вручную. |

Команда `./gradlew clean` или `.\gradlew.bat clean` очищает результаты сборки без удаления исходников. Это не обязательный шаг при открытии проекта.

### Обязательно оставить для обычной сборки

- `app/src/` целиком: Kotlin, XML, картинки, манифест;
- `app/build.gradle.kts`;
- корневые `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`;
- каталог `gradle/wrapper/`, включая **`gradle-wrapper.jar`**;
- `gradlew` и `gradlew.bat`.

Слова `gradle` и `gradlew` относятся к сборщику Gradle, а не к Git. Удалять их, чтобы «убрать GitHub», не нужно. Для переноса между Windows и Linux лучше сохранить оба скрипта.

Для сдачи исходников можно исключить `.git`, `.gradle`, `.kotlin`, `.idea`, `build`, `app/build` и `local.properties`, сохранив исходники и Gradle Wrapper. README лучше оставить как инструкцию. Для установки на телефон нужен только APK.

## 13. Проверка перед сдачей

Автоматическая проверка Actions — Android Lint и компиляция APK. Эмулятор и тесты интерфейса в workflow не добавлены. Поведение на телефоне нужно проверить отдельно:

1. Запуск сразу открывает ленту; все три картинки видны и список прокручивается.
2. Все четыре нижние кнопки открывают соответствующий раздел.
3. Поиск `самара`, `САМАРА` и ` Самара ` даёт одинаковый результат.
4. Поиск несуществующего имени показывает сообщение об отсутствии людей.
5. «Добавить» увеличивает число друзей; «Убрать» уменьшает его.
6. Добавленный друг остаётся добавленным после закрытия и повторного запуска.
7. «Написать» у Анны открывает чат Анны с демонстрационными сообщениями.
8. Новое сообщение появляется справа, время видно, поле очищается.
9. Пустое сообщение и пробелы не добавляются.
10. В другом диалоге не появляется текст, отправленный Анне.
11. После возвращения в список диалогов видна последняя реплика.
12. «Избранное» сохраняет заметку, которая остаётся после перезапуска.
13. В профиле можно сохранить имя, город и «О себе»; без фото инициалы обновляются.
14. «Выбрать фото» открывает системный выбор; выбранное изображение появляется круглым и остаётся после перезапуска. Отмена выбора сохраняет прежний аватар.
15. Фото есть у Анны и Максима, у остальных — инициалы. В обычном чате нет поясняющей подписи, в «Избранном» она есть.
16. Пустое имя не сохраняется и показывает ошибку у поля.
17. При повороте сохраняются выбранная вкладка и ввод в полях; чат не дублирует отправленные сообщения.
18. В авиарежиме все перечисленные действия работают так же.

## 14. Частые проблемы

| Ошибка / ситуация | Что сделать |
|---|---|
| Studio открыла только папку с кодом | Открыть корень с `settings.gradle.kts`. |
| `SDK location not found` | Установить SDK и проверить его путь в Studio / `local.properties`. |
| Не найден SDK 35 | Установить Android SDK Platform 35 через SDK Manager. |
| Ошибка Java при Sync | Проверить, что Gradle JDK — 17. |
| Gradle не скачивается | Прочитать ошибку Sync: проверить сеть, прокси, доступ к адресам и Offline Mode. |
| `Permission denied` для `gradlew` | Выполнить `chmod +x gradlew`; на Windows использовать `.\gradlew.bat`. |
| Ошибка `R` или ресурса | Исправить первую ошибку Kotlin/XML в Build Output и повторить сборку. |
| Новые данные из исходников не видны | Пересобрать и установить APK; уже сохранённые истории и профиль не заменяются демонстрационными значениями. |
| Собеседник не отвечает | Это локальная оболочка. Входящие реплики заданы в коде, реального собеседника нет. |
| После удаления приложения исчезли сообщения | Это ожидаемо: данные хранились внутри приложения на телефоне. |
| Android не устанавливает APK поверх старого | Проверить несовпадение подписей; перед удалением старой версии учесть потерю её локальных данных. |
| В Actions нет APK | Проверить результат сборки и срок хранения artifact; при необходимости запустить снова. |
| Release уже существует | Использовать новый тег для следующего выпуска. |

## 15. Краткое объяснение для защиты

Приложение является учебной оболочкой социальной сети. Оно написано на Kotlin, общая разметка экранов находится в XML. Основная Activity содержит четыре раздела с переключением через ViewFlipper. Лента и список людей заполняются из встроенных данных. Поиск фильтрует людей по имени и городу. Друзья, профиль и переписки сохраняются локально в SharedPreferences; сообщения сериализуются в JSON. Для переписки открывается отдельная Activity, где входящие и исходящие сообщения располагаются с разных сторон. Отправка только добавляет сообщение в локальную историю, сетевого обмена и авторизации нет. Сборкой управляет Gradle; GitHub Actions выполняет Lint, собирает APK, а по тегу публикует релиз с APK и исходниками.
